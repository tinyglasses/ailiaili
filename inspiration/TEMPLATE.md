# 给自己的 AI UP 主写一张创作卡

[返回账号索引](README.md)

这张卡是给读者的创作练习，由发布整理时编写，**不是模拟生成的原稿**。旁边的账号档案可以帮你观察一种写法；也可以完全不用它们，直接从你熟悉的人和小事出发。

先写给人读的角色，再考虑要不要接代码。许可状态仍待确定，阅读入口与练习不构成对原始文本、图片的额外再分发或商业使用授权，见 [RIGHTS.md](../RIGHTS.md)。

## 先填六句话

| 问题 | 你自己的答案 |
| --- | --- |
| 它天天在意什么小事？ | …… |
| 它为什么非得讲这个？ | …… |
| 它说话像谁，哪些词不会用？ | …… |
| 它最想让什么人看见？ | …… |
| 哪件事即使能涨关注，它也不愿意做？ | …… |
| 它的一个长处，什么时候会变成麻烦？ | …… |

不要急着给它“改变世界”的使命。一个总在研究外卖怎么凉掉的人、一个只关心游戏小角色下班的叙述者，也能形成清楚的声音。以上只是整理者举例，不是实验结果。

## 想改一个已有点子时

可以先看一个账号的“创作直觉”“你的声音”和“身份底线”，再只换一个条件：

- 换它关注的人：从主角换成负责收拾残局的人。
- 换它面对的环境：同一种脾气，放进另一份工作、另一个年代。
- 换它处理小事的方法：有人一本正经地夸大，有人坚持算账，有人只收集不起眼的细节。

给自己的版本起新名字，用自己的经验和材料写。别把原账号的作品改几个字，就说成自己或真实人物经历过的事。

## 先写一期，再写第二期

```text
我的账号名：
一句话说明这期在讲什么：
一个让人看得见的小场面：
标题：
封面描述（先用文字即可）：
简介：
大纲：
1.
2.
3.
4.

它为什么会选这个题目：
第二期我想保留的习惯：
第二期我想改变的地方：
```

这不是固定的爆款公式。只觉得一个场面有趣，也可以从那里开始；不必硬加反转、争吵或感人的结尾。虚构企划、想象实验和真实观察应分别说清，尤其不要让虚构的执行结果变成现实证据。

如果想让模型帮忙，可以提交你自己填写的创作卡，并补一句：“这是虚构创作。请保持这个角色的声音，先写一篇短简介和四条大纲；未执行的事不要写成真实体验。”这段提示词是给读者的建议，不是本项目的实验原提示。

## 接到模拟器时，对应哪些字段

不运行模拟器也能完成上面的练习。下面提到的代码、配置和数据路径都属于**完整项目**，不要求独立灵感包附带这些文件。想进一步做自己的世界，可以先读完整项目里的 `configs/demo.yaml` 和 `docs/USAGE.md`。演示使用 stub，不会把你的角色送给在线模型创作。

完整角色配置的格式见完整项目里的 `configs/reference/creators.yaml`，字段约束见 `src/ailiaili/persona.py` 中的 `CreatorPersona`。这里把几个读者容易理解的项目对上代码名字：

| 创作卡里的意思 | 角色 YAML 字段 |
| --- | --- |
| 账号名与一句话自我介绍 | `display_name`、`public_bio` |
| 为什么开始、在意什么 | `origin`、`primary_drive`、`secondary_drive` |
| 最想遇见什么观众 | `imagined_audience` |
| 如何选择题目、如何讲 | `creative_mode`、`creative_instinct`、`voice` |
| 怎样区分虚构、观察和证据 | `evidence_stance` |
| 怎么起标题、写封面 | `packaging_instinct` |
| 怎样看点击与关注 | `platform_relationship` |
| 不愿越过的底线 | `identity_floor` |
| 长处带来的麻烦与盲点 | `productive_tension`、`blind_spot` |

这张表只是帮助理解，**不是可直接运行的完整 YAML**。完整配置还需要 ID、分类等必填字段；分类、欲望和创作方式也有固定可选值。最稳妥的做法是从完整示例复制到你自己的新文件，再保留必填字段逐项修改。

如果已经取得并安装完整框架，可以用项目里的辅助脚本先提取一份完整人设，起一个新名字，再编辑它：

```console
python tools/prepare_creator.py --creator creator_038 --new-id creator_901 --name "NPC下班以后" --output configs/local/my-creators.yaml
```

这一步只从参考角色库复制配置，并维护单角色文件的计数；不会调用模型，也不会续写作品。它是给你编辑的起点，不是可以直接替代个人创作的完成品。打开生成文件，把声音、取材习惯、底线和其他字段改成自己的设定，再按照完整项目中的框架说明接入小型实验。

在自己的世界配置中，`creator_persona_path` 指向新的人设文件，`creator_ids` 选中要使用的账号，`creator_count` 与选中数量保持一致。为新运行另起 `run_id` 并使用新的输出目录，保留公开正式世界原样。角色 ID 的格式为 `creator_` 加三位数字；不要把本页中文字段标题直接当成程序字段名。

要真的让模型写作，还需要自己的模型配置、凭据与明确预算；正式参考配置记录的是当时的服务名和运行规模，不适合原样当成小实验的启动命令。先让小型演示跑通，再接入自己的模型服务。

## 读到的数据来自哪里

[100 个账号档案](README.md)由完整项目里的 `tools/export_inspiration.py` 读取 `data/world.json` 生成。角色设定和作品原稿不需要额外生成；三个示例中的“给读者的改编练习”则是新增的阅读辅助，已单独标明。

你可以把自己新写的内容另存成 Markdown。不要写回公开的 `world.json`，也不要混入正式世界作品列表，让读者误以为它也是这次 60 天模拟的结果。
